## Среда

Python 3.11, Java 17, PySpark 3.5.7 и Docker Desktop.
Для входа используется `telethon==1.46.0`. Версия 1.24.0 из условия получает от Telegram ошибку UPDATE_APP_TO_LOGIN. Kafka — `kafka-python==2.0.2`.

Из корня репозитория:

```sh
cd DZ_3
uv venv --python 3.11 .venv
source .venv/bin/activate
uv pip install -r requirements.txt
```

В VS Code выбрать ядро `DZ_3/.venv/bin/python`. Команда `java -version` должна показывать Java 17.

## Запуск задания 1

1. Создать приложение в [API development tools](https://my.telegram.org) и получить `api_id` и `api_hash`.
2. Выполнить `cp .env.example .env` и заполнить оба значения в `.env`. Файл остаётся локальным.
3. Запустить Docker Desktop, затем Kafka и создать топик:

```sh
docker compose up -d
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --if-not-exists --topic telegram_messages --partitions 1 --replication-factor 1
```

4. Выполнить ячейки тетради задания 1. Последняя ячейка будет ждать сообщения.
5. В другом терминале из папки `DZ_3` запустить сборщик:

```sh
source .venv/bin/activate
python telegram_producer.py
```

При первом входе Telegram запросит номер телефона, код входа и, если установлен, пароль двухэтапной аутентификации. Эти данные вводятся только в терминале. Сессия `telegram.session` хранится локально.

Сборщик подключается к восьми каналам из условия. Если Telegram ещё не знает канал по ID, программа запросит его ссылку или `@username` и проверит соответствие ID. Для недоступного или закрытого канала понадобятся действующая ссылка и доступ к нему; по одному ID их получить нельзя.

Схема: Telegram → Kafka → локальный TCP-поток → Spark Streaming. TCP нужен для DStream в PySpark 3.5, где нет Python-модуля Kafka. Оба окна и подсчёт выполняются в Spark.

Каждые 30 секунд тетрадь выводит `username` и количество сообщений за последние 1 и 10 минут по убыванию количества. Учитываются новые сообщения после запуска потока. Окна считаются по времени поступления в Spark, а не по дате публикации. В начале работы окна ещё не заполнены целиком.

Если username отсутствует, используется ID отправителя. В анонимных публикациях Telegram может сообщать ID канала вместо автора.

Для остановки: Interrupt в тетради, Ctrl+C в терминале сборщика, затем `docker compose stop`. Перед повторным запуском всех ячеек перезапустить ядро.

## Запуск задания 2

Используются те же Kafka, топик, сборщик и `.env`. Выполнить ячейки тетради задания 2. Если сборщик уже работает, оставить его запущенным. Тетради используют разные TCP-порты (9999, 9998 и 9997), поэтому могут работать одновременно.

Слова отбираются по правилу из условия: русские буквы и заглавная первая буква. Регистр приводится к нижнему, гласные и «й» в конце удаляются. Первое слово предложения учитывается, стоп-слова не используются.

Каждую минуту весь накопленный результат сохраняется по убыванию частоты в `Задание 2/output/<запуск>/<минута>/part-00000`. Формат строк: `слово, количество`. В соседней папке `checkpoint` Spark хранит состояние потока. Результаты и checkpoint остаются локально.

Последняя ячейка работает 30 минут и после остановки выводит топ-10. Для сдачи нужен запуск с настоящими сообщениями Telegram не менее 30 минут; тестовые сообщения его не заменяют.

## Запуск задания 3

В исходном условии задания 3 оставлен TODO. Реализован согласованный вариант: правила задания 2 с отдельными частотами и топ-10 для каждого канала.

Порядок запуска тот же. Сборщик уже передаёт `channel_id`, дополнительные настройки не нужны.

В течение 30 минут каждую минуту сохраняется весь накопленный результат в `Задание 3/output/<запуск>/<минута>/part-00000`. Формат: `ID канала, слово, количество`. Строки сгруппированы по каналу, внутри канала отсортированы по убыванию частоты. После остановки выводится до 10 слов каждого канала. Каналы без подходящих слов не выводятся.
